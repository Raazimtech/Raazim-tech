Google adds file-slicing controls to the Gemini API

Developers can direct Gemini to inspect selected pages, spreadsheet cells or audio and video segments instead of asking it to process an entire file in one pass.

Raazim Tech Editorial DeskPublished 24 November 2026 · 10:54 EAT3 min read

Google has introduced native file-slicing controls for the Gemini API, giving developers more precise control over which parts of a document or media file a model processes. The announcement, published on November 23, covers PDFs, Microsoft Office and OpenDocument files, spreadsheets, audio and video.

Rather than sending every page, worksheet or minute of a recording into a model's context, an application can request a narrower selection. Google says token usage is billed for the content selected for inspection.

What developers can select

The new controls vary by file type. For documents and presentations, developers can specify a page range and choose whether the model receives extracted text or page images. For spreadsheets, they can select a worksheet and a visible cell range, with options for values, formulas and visuals.

For audio and video, developers can select time intervals and choose relevant content layers, such as transcripts, audio or video frames. Google also says a file uploaded through its Files API can be reused by URI across multiple turns and tool calls.

  • Documents: selected pages and text or image layers.
  • Spreadsheets: selected worksheet tabs and cell ranges.
  • Video: selected time ranges, frames, audio and transcript layers.
  • Audio: selected time intervals.

Why this matters for AI applications

Many business workflows involve long contracts, reports, slide decks, spreadsheets and recordings. Processing an entire file can consume context and make it harder to focus on the section relevant to a question. Targeted selection gives developers a way to inspect a document in stages: scan for the relevant area, then request a closer look at that portion.

This could be useful for research assistants, document review tools, customer-support systems and agents that need to examine files as part of a larger workflow. It also gives developers more control over the balance between detail, latency and token usage.

Important limits and security considerations

File slicing does not remove the existing file-size and page limits, which still apply to the uploaded file. Developers should also avoid treating selective processing as a privacy or redaction feature. Before uploading confidential material to any external AI service, they should review the provider's data-handling terms, permissions and retention settings.

Raazim Tech takeaway

This is a practical developer feature, not a new standalone AI model. Its value is in making file-heavy AI workflows more selective and easier to control. Teams should test accuracy and actual usage costs with their own documents before assuming savings.

What to watch next

The important next step is real-world evaluation. Developers should compare sliced and unsliced workflows for answer quality, token usage and failure cases, especially when relevant information spans multiple pages or spreadsheet tabs.
